# ADR-001: 中英双语 README 与红绿灯测试体系

## Status
Accepted

## Date
2026-06-01

## Context

项目经过两周的密集开发，核心功能（搜索→分类→生成 README）已跑通，收录 370 个项目、10 个分类。本次会话集中讨论了以下几方面问题：

### 1. 需求文档不完整
原有 `docs/REQUIREMENTS.md` 缺少 PRD 关键要素：目标用户、成功标准、范围声明、风险分析、未决问题、Roadmap、术语表。同时文档中存在大量过时内容（待确认引用、导航描述与实际不符等）。

### 2. README 信息密度和视觉层次不足
- 统计区仅有 4 行总数，看不出各分类分布
- 导航栏挤在一行，分类多时难以阅读
- 精选推荐和全部项目之间没有视觉区分，缺少编号和数量提示

### 3. 展示语言单一
README 为纯英文。中文开发者看项目描述需要额外理解成本，且很多热门项目没有官方中文介绍。

### 4. 代码中存在多处死代码
- `uncertain` 机制在引入 priority 系统后永不触发，但相关代码未删除
- `_sourceCategory` 字段写入但无人读取
- `needs_review` 字段写入但无人消费
- `page > 10` 条件因 while 限制不可达

### 5. 无自动化测试
三个脚本无任何测试。修改分类逻辑或 README 生成逻辑时无安全网。

### 6. 导航分组硬编码
`navGroups` 映射（分类 → 导航分组）直接写在 `generate-readme.js` 中。新增分类时若忘记同步更新导航映射，新分类不会出现在导航表中。

## Decisions

### 1. README UI 改版
**统计区：** 4 行简单总数 → 两列分类明细表（5 行 10 分类）。
**导航区：** 单行 `·` 分隔链接 → 4 列分组表格（概览/AI 工具方向/代码方向/平台方向）。
**精选推荐：** 增加 🥇🥈🥉 奖牌编号 + `（Top 5 / 共 N）` 标题提示。
**全部项目：** 跨精选-全部连续编号（#1-#5 精选，#6 起全部项目），用 `━━━` 长横线分隔。

### 2. 中英双语展示
**每项目始终输出 🌏 中文 + 📝 英文两行。**
中文描述来源优先级：
1. 项目自带的 `README.zh-CN.md`（自动抓取）
2. `data/chinese_descriptions.json` 缓存（AI 翻译写入）
3. 英文描述本身含中文
4. 均未命中 → 显示 `*中文描述待补充*` 占位

**AI 翻译不进 GitHub Actions。** 由维护者手动触发 Reasonix 执行翻译并写入缓存。

**翻译成果：** 370 个项目全部完成中英双语展示。

### 3. 红绿灯测试
**框架：** Node 内置 `node:test` + `node:assert`，零外部依赖。
**测试文件：** `test/classify.test.js`（29 个测试，8 组）。
**覆盖范围：**
- 分类核心逻辑（topic/desc 匹配、优先级裁决、边界情况）
- 手动覆盖（hidden、强制分类）
- 格式化函数（Stars 缩写、锚点生成）
- 导航分组一致性（所有分类都在 `nav-groups.json` 中有归属）
- README 输出格式（🥇编号、🌏📝平衡、精选标题）
- 数据完整性（无重复项目、hidden 一致性、合计行一致）
- 导航表格格式（4 列验证）

**测试隔离：** 使用 `test/fixtures/` 下的 mock 数据，不碰真实 `data/` 文件。通过 `isMain` 守卫避免 `import` 时触发 `main()` 自执行污染测试输出。

### 4. 死代码清理
删除或清理：
- `uncertain` 数组及相关逻辑（`classify.js` + `generate-readme.js`）
- `_sourceCategory` 字段（`fetch-repos.js` + 存量数据文件）
- `needs_review` 数据（`manual_overrides.json`，3 个项目移入 `overrides.hidden`）
- `page > 10` 不可达条件（`fetch-repos.js`）
- `_uncertain` 死引用（`translate-desc.js`）

### 5. navGroups 抽离为配置文件
创建 `config/nav-groups.json`，将导航分组映射从代码移到配置。新增分类时需同步更新此文件。测试 `导航分组一致性` 会检查此约束。

### 6. 快速入口文档
创建 `docs/SKILL-GUIDE.md`，记录项目各阶段的推荐 skill 使用流程，方便后续快速查阅。

## Alternatives Considered

### 中文描述生成方式
- **方案 A（选择）：** AI 翻译缓存，由 Reasonix 手动执行，写入 `chinese_descriptions.json`
- **方案 B：** 在 GitHub Actions 中调用翻译 API → 被拒（需要 API key，增加 CI 成本和失败点）
- **方案 C：** 完全依赖 GitHub 自带的 README.zh-CN.md → 被拒（覆盖率太低，370 个项目 0 个有中文 README）

### 测试框架
- **方案 A（选择）：** `node:test` 内置 → 零依赖，Node 24 原生支持
- **方案 B：** Jest / Vitest → 被拒（需要安装依赖，本项目足够轻量不需要）
- **方案 C：** 无测试 → 被拒（修改分类逻辑时无安全网）

### 导航分组配置
- **方案 A（选择）：** `config/nav-groups.json` JSON 文件
- **方案 B：** 在 `categories.json` 中扩展 `group` 字段 → 被拒（关注点分离，分类定义和导航渲染是不同职责）
- **方案 C：** 保持硬编码 → 被拒（未来新增分类时容易遗漏）

## Consequences

### Positive
- README 信息密度大幅提升，统计/导航/精选层次分明
- 所有项目中英双语展示，中文开发者友好
- 29 个红绿灯测试为后续修改提供安全网
- 代码库死代码清除，降低了认知负担
- nav-groups.json 配置化，新增分类时只需改 JSON 不用改代码
- SKILL-GUIDE.md 降低了后续会话的入门成本

### Negative
- 中文描述完全依赖手动 AI 翻译，GitHub Actions 自动更新不会补充新项目的中文描述
- 29 个测试中部分依赖真实 README.md 输出，修改渲染逻辑时需要同步更新测试期望值
- config/ 目录新增一个文件（nav-groups.json），项目管理成本略有增加

### Technical Debt
- `renderRepoLine` 函数未导出为测试专用函数，当前通过检查 README 输出间接测试
- `fetch-repos.js` 仍缺少测试（需要 GitHub Token，不适合 CI）
