# ADR-002: 使用优先级系统自动消歧义多分类匹配

## Status

Accepted

## Date

2026-05-31

## Context

许多 GitHub 项目同时打多个 topic 标签，如一个项目可能同时有 `mcp`、`ai-agents`、`automation` 三个标签，匹配到 MCP、Agent 工作流、浏览器自动化三个分类。最初的做法是标记为"待确认"（uncertain），让用户手动决定。

结果产生了 203 个待确认项目，用户无法逐一 review，合集质量受影响。

## Decision

引入分类优先级系统（priority 1-10），当项目匹配多个分类时，自动取优先级最高的那个。

## Alternatives Considered

### 标记为待确认，用户手动处理

- Pros：最准确，用户决定
- Cons：203 个待确认，用户根本看不过来，待确认区形同虚设
- Rejected：不可维护

### 关键词权重评分

- Pros：理论上更精细
- Cons：需要维护权重表，增加了复杂度，效果未必比优先级好
- Rejected：过于复杂

### 优先级系统（选定）

- Pros：
  - 简单明确，每个分类一个数字
  - 自动消歧义，无需人工介入
  - 配置驱动，修改优先级只需改 JSON
- Accepted

## Priority 赋值逻辑

| 优先级 | 分类 | 理由 |
|:------:|------|------|
| 10 | MCP | 最具体的协议标签，不会误判 |
| 9 | AI Coding Agent | 明确面向编码场景 |
| 8 | 代码分析 | 明确的技术领域 |
| 7 | 代码导图 | 明确的可视化方向 |
| 6 | 浏览器自动化 | 明确的使用场景 |
| 5 | 评估/可观测 | 明确的质量领域 |
| 4 | AI 网关 | 明确的基础设施层 |
| 3 | 本地推理 | 明确的运行方式 |
| 2 | LLM 框架 | 较宽泛，很多项目都算 |
| 1 | Agent 工作流 | 最宽泛，几乎所有 AI 项目都可以算 |

## Consequences

- 待确认项目从 203 降为 0
- 自动分类的准确率取决于优先级赋值是否合理
- 如果某个项目被优先级的"误杀"，通过 `manual_overrides.json` 修正
- 优先级可在 `config/categories.json` 中随时调整
